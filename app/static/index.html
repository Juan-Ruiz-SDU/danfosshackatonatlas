        1 Copy of Danfoss's website

            Open ↗
          
          
        
          
      
          
      
          How the website spreads authority
          
      
          Search engines pass authority through links: every page should be reachable from the first page
        in few clicks, linked from related pages, and listed in the sitemap. All its text should be in the HTML.
          
      
          
    
          

    
          
      
          3 Edit this page: 
          
      
          Markdown: # Title, ## Section, ### Sub-section,
        - list, | table |, [link](https://...), and catalog tiles as
        - [Title](https://...): description. The lines between --- at the top are the page's
        title, description and address. Links to other pages of the website stay links between them. Facts must come
        from the wiki: the check below flags new numbers that are not in it.
          
      
      
          
        
        
      
          
      
          A wiki block is a line like {{wiki: platforms/heat-pump-platforms}} (or
        {{wiki: technologies/micro-plate-pattern#Benefits}} for one section). When the website is built
        it is replaced by that part of the wiki as it is now, so when the team updates the wiki, the page follows.
          
      
          
      
          
        
        
      
          
    
          

    
          
      
          Against the competitors: what to add
          
      
          For each buyer question: where this page ranks against the saved competitor pages (best passage
        and whole page), which page beats it, the question's words the winner has and this page lacks, and the wiki
        blocks that contain them. Train the page by adding those wiki blocks under a heading in the buyer's words,
        never the competitor's text. Check the holdout questions too (see wiki/guidelines/competitor-training.md).
          
      
          
    
          

    
          
      
          
        
          Fact check: is every claim backed by a source?
          
        
          Each sentence, list item and table row is checked against the wiki facts, the original
          documents in raw/ and Danfoss's own pages. Claims copied from a source pass at once; every
          number must appear in the matching source; the rest goes to a grounding checker (Bespoke-MiniCheck if it is
          installed in Ollama, otherwise the Run tab's answer-box AI, which must quote the exact supporting words).

          1 Ask Gemini with Google Search
          
      
          The agent asks Gemini every buyer prompt in prompts/prompts.txt with Google Search
        switched on. It records the searches Gemini runs (its sub-queries), the pages it cites and how much of the
        answer each page supports, then imports those pages as text. Every update is kept, so you can see how the
        citations change. AI Overviews has no public API: reading it needs a paid search-results service.
          
      
          
      
          
        
        
        
        
        
      
          
      
          
        
          
        
          
      
          
    
          

    
          
      
          2 How the citations change
          
      
          One line per update. Share = the part of Gemini's answers a site supports, on average per prompt.
        Gemini gives no score per page: this share, measured from its answer, is the closest real number.
          
      
          
      
          
      
          
      
          
    
          

    
          
      
          3 Answers of one update
          
      
          
        
          
      
          
    
          

    
          
      
          
      
          
      
          What Gemini cited, and how much of its answer each page supports
          
      
          
      
          Gemini's searches (sub-queries) and our page
          
      
          For each search Gemini ran: where our page's best passage ranks among the cited pages' passages
        (BM25), and which page leads. A sub-query is answered when our page has a passage that leads it: a section
        whose heading and first sentence answer that search directly, with the facts.
          
      
          
      
          Why these pages? (AI reviewer)
          
      
          The reviewer sees plain-text passages of the same length, brand names hidden and the order
        shuffled, so markdown and length cannot count. It scores each on checkable signals and explains. Its total
        is then compared with Gemini's real shares: high agreement means the reviewer judges like the engine.
        Uses the "AI that plays Google's answer box" from the Run tab.
          
      
          
        
        
          
      
          
      
          
        
        From this explanation: changes to the wiki so the next pages answer these searches. Nothing changes until you accept.

          1 The process
          
        
          
        
          
      
          
      
          
        
          2 Sub-queries: what the page must answer
          
        
          Gemini's real searches come first (Citations tab), then the buyer questions, then searches the
          writer AI adds. A search with no evidence in the wiki gets no section: it is a fact to find, not text to pad.
          
        
          
      
          
      
          
        
          3 Evidence for one section
          
        
          Each candidate passage with its rank in each step. BM25 finds the exact words, the embeddings find
          the meaning, RRF fuses both ranks, the reranker grades how well it answers (0–3). The chosen ones (✔) are the only
          text the writer sees for this section.
          
        
          
        
          
        
          The section, sentence by sentence
          
        
          
      
          
      
          
        
          4 The embedding map
          
        
          Every passage turned into a vector by the embedding model, flattened to 2-D (PCA). Close points mean
          similar meaning. Stars are the sub-queries; lines join each one to the evidence its section used.
          Competitor passages near a star are what we compete with for that search.
